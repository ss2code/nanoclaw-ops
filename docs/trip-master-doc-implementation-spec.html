Trip Master Document — Implementation Spec

Implemented 2026-07-08. Scope: deterministic trip master document generation, route/map support, deploy-only Netlify artifact workflow, skill instructions, and focused tests.

Principles

  • Document format and deployment are separate. trip-docs owns master/research/free document types, compose, bump, render, anchors, and prose blocks. artifact-deploy owns generic hosted deployment for any agent group.
  • Scripts compute; the model judges. Route strips, tabs, anchors, ops summaries, password bundles, and deploy manifests are deterministic code paths with tests.
  • No automatic Netlify deploys. To preserve free-tier usage, agents must not deploy unless the user explicitly asks. A successful deploy response goes back to the active chat surface, for Trip Companion this means WhatsApp, with the running URL and version.

Command Surface

Trip documents

TD="bun /app/skills/trip-docs/scripts/trip-docs.ts --dir /workspace/agent"
$TD new scotland --title "Scotland 2026 — Master Document" --type master
$TD compose scotland --db trip.db
$TD bump scotland --summary "locked Skye route and added Portree stay"
$TD render scotland

Generic deployment

AD="bun /app/skills/artifact-deploy/scripts/artifact-deploy.ts --dir /workspace/agent"
$AD netlify setup --site <site-name> --state-db trip.db
$AD netlify set-password --state-db trip.db
$AD netlify bundle --input scotland.html --slug scotland --state-db trip.db
$AD netlify deploy --input scotland.html --slug scotland --site-id <site-id> --state-db trip.db
$AD netlify status --state-db trip.db

Deployment rule: do not run netlify deploy, set-password, rollback, or teardown unless the user explicitly asks. After deploy, reply in WhatsApp with the running URL and document version.

State and Files

  • blocks/<slug>/*.html stores authored prose blocks. Compose preserves these blocks.
  • Generated HTML regions use <!-- gen:name sha256=... --> markers. If a generated region is hand-edited, compose refuses to overwrite it.
  • version.json is written beside the document for hosted reload checks.
  • deploy_state in an optional state DB stores Netlify site, password hash, last bundle, last deploy, and rollback metadata.
  • .deploy/<slug>/ is the deterministic Netlify bundle directory.

Operational Notes

  • The Netlify token is assumed to be installed in OneCLI for api.netlify.com. The deploy script omits an Authorization header when no local NETLIFY_AUTH_TOKEN is present so OneCLI can inject credentials.
  • The Edge Function source is included in every bundle. Static file deployment uses Netlify's file-digest API; if live edge-function upload semantics need additional Netlify-specific packaging, use the generated bundle as the stable source artifact and verify once with a user-approved deploy.
  • The original design's trip-specific deployment module has been generalized to artifact-deploy so any agent group can use the same Netlify workflow for any HTML artifact.
