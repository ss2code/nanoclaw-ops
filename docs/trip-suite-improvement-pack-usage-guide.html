Trip Suite Improvement Pack — Usage Guide

The scripts are authoritative: agents relay computed results rather than doing date, feasibility, or money calculations in chat.

Daily operation

  • After every confirmed stage change, reconcile heartbeat tasks: one daily pre-trip task, two on-trip tasks (morning and evening), and one post-trip task every three days. The CLI JSON wakeAgent is authoritative.
  • Keep venue hours, pace, alternates, booking references, and UPI opt-in in trip.db. The migrations are additive and safe for existing trips.
  • Before changing an on-trip day, dry-run trip-planning day shuffle; share its board and feasibility result, then use --commit --by <member> only after approval.

Common commands

TC="bun /app/skills/trip-core/scripts/trip-core.ts --db /workspace/agent/trip.db"
TP="bun /app/skills/trip-planning/scripts/trip-planning.ts --db /workspace/agent/trip.db"
TF="bun /app/skills/trip-finance/scripts/trip-finance.ts --db /workspace/agent/trip.db"

$TC heartbeat --edition morning
$TP place set --id 8 --open-hours "09:00-17:00"
$TP config set-pace --minutes 300 --by 1
$TP day shuffle --date 2026-08-15 --drop 23
$TF burn
$TF settle --links

For an uneven receipt, use $TF log --items …; item amounts must exactly match the total and every named person must be active on the expense date. For returning travellers, export tagged preferences from the old memory store and import them into the new one; imports remain auto until the new trip owner curates them.

Vendor workflows can derive missing fields from stays:<id> or legs:<id> with --db … --from …; explicit --missing overrides derivation. All outbound messages remain draft-and-review operations.
