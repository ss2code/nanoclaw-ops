HOW TUTOR FOUNDRY WORKS

Rooms first, containers on demand

There is no permanent tutor container to create manually. Tutor Foundry prepares the class wiring, and NanoClaw starts an isolated session container only when a paired room needs it.

01

CHANNEL PREREQUISITE

Configure Telegram once

The Telegram bot token belongs to NanoClaw’s normal channel setup. Tutor Foundry never asks you to paste it here and it is not a student or tutor credential.
02

CLASS DRAFT

Describe the class

Enter the class, subject, tutor, and student personas. Saving this draft changes only the local Foundry record.
03

ROOM PROOF

Pair the rooms

Generate a one-time four-digit code and send it from the right Telegram account in the right private group. Foundry records the verified user and group route; no container is needed for this.
04

CLASS WIRING

Create the tutor application

Launch creates the agent group, class and student app databases, memberships, and shared-mode wires. The tutor and each student keep separate chat sessions while sharing the class knowledge state.
05

FIRST MESSAGE

Wake a session container

When the tutor or a student sends the first routed message, NanoClaw creates that chat’s session container. Later messages reuse it until the host retires it; another room has its own session container.

WHAT IS TIED TO WHAT?

Pairing code
One-time proof that the sender controls a Telegram user and group. It is not a long-lived secret.
Bot token
One global channel credential configured outside Foundry. It is not bound to a student, tutor, or container.
Class wiring
The durable link between one agent group and the tutor/student messaging groups.
Session container
An on-demand runtime for one chat session. It is created after launch, not during pairing.

COMMON QUESTIONS

Can I pair before the container exists?

Yes. That is the intended order. Pairing happens in the host’s Telegram interceptor and stores the verified route before any agent session wakes.

Should I create one container for the whole class?

No. Create one class wiring. NanoClaw manages per-room session containers automatically, while the tutor application remains shared at the agent-group level.

What should happen after launch?

Send a simple message in the tutor control group and each student group. Then use Status to confirm the class is initialized; coursework review and ingestion happen through the tutor control chat.

Recommended orderConfigure the bot in NanoClaw → define the class draft → pair tutor and student rooms → create class wiring → send the first message → ingest and teach.
