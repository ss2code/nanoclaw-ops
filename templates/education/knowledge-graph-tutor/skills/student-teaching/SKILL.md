name: student-teaching
description: Run a grounded tutoring turn using routing-scoped state, the eligible concept frontier, shared course retrieval, and per-student evidence. Use for student questions, practice, assessment, hints, feedback, and scheduled reviews.
---

Follow the standing turn policy. Create one opaque turn trace ID and emit generic workflow receipts for the major steps with `record_workflow_event` (resolve, frontier, decision, retrieval, assessment, and mastery); RUNS should be able to inspect the workflow even when the tutor application is absent. Call `inbox apply`, `context current`, `context frontier`, `learning plan-action`, and `course search --trace <id>` before teaching. The returned audience profile is mandatory: phrase the entire turn at its ELI target, keeping the curriculum's real cognitive demand without childish simplification or unexplained expert shorthand.

Choose only from the returned pedagogy candidates. When `plan-action` returns an `assessment`, ask its authored `action.prompt`; do not reveal `expected_evidence`, rubric scoring notes, or the linked answer before the student responds. The active blueprint governs selection and repeat exposure. Attribute the response to that exact material question with `learning record-attempt --item <action.source_item_id>` so unseen-question selection, answer-backed error analysis, revision-safe evidence, and tutor statistics remain accurate. When a rubric is returned, assess each criterion and pass `--rubric-scores`, plus `--grading-confidence`, `--selected-option` for choice questions, and `--hint-count`. If you must generate a question, match the ELI target and explicitly distinguish it from authored source material.

Use `instruction list` or `instruction search` before making a new explanation artifact. Prefer a concise inline explanation for ordinary Telegram teaching; use `send_file` only when the student asks for the full lesson, worksheet, diagram, HTML, PDF, or original source. A catalogue result's `text_alternative` is the accessible fallback, while `preview_path` is the resend artifact. For a source-backed request, call `ingestion source-list --graph <slug> --json` and then `ingestion source-get --id <approved-document-id> --json`; use only the returned student-visible path and never expose uploader or private metadata. Invoke `learning-visuals` and the globally mounted `diagram-design` skill whenever a simple concept or relationship is materially clearer as a diagram; propose reusable generic diagrams with concept and audience tags. If the student asks to see a material again, call `instruction list --concept <canonical-id> --json` or `ingestion source-get --id <id> --json` and use the returned `preview_path`, `normalized_path`, or approved artifact path with `send_file` in this same student channel. Use the inline Unicode fallback when Telegram cannot render or deliver the requested file. For a `PROACTIVE_COACHING` turn, also call `coaching briefing --slot ... --json` and make its single `next_work` card the finish line for the next slot. Choose encouragement from observed progress only; points and streaks are motivation, not mastery evidence.

Record an attempt only after an assessable student response, with a unique idempotency key, the same `--trace`, and `--evidence` containing a bounded verbatim or faithful excerpt of the observed answer. Never invent evidence or create a probe event while asking the opening question. Positive mastery moves immediately from accumulated evidence; a later negative assessment may regress it and should drive the next frontier action. Use `learning set-action` when expecting a follow-up. If syntax is uncertain, use command-level `--help`; do not try `students list`, `frontier eligible`, `concept get`, or direct SQLite queries. Never accept or pass a student selector.
